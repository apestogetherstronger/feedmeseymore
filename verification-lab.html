03 / What decides pass or fail?
Give the tests a trusted reference.
An oracle is the rule that decides whether a result is correct. Different oracles expose different kinds of mistakes.
Coverage measures which lines ran. Mutation testing asks whether your checks noticed a deliberately planted fault. Neither alone proves correctness.


04 / Put distance between author and verifier
From a ticket to inspectable evidence.
Define “done”
Name the actor, starting state, action, visible and stored outcomes, threshold, oracle, and dependencies that must be real. A person reviews the contract before code.
Make wrong behavior fail
For a bug, reproduce it before fixing it. Save the exact error, stack trace, command, output, and root-cause file and line. Keep investigation in a separate context.
Implement one step
Use one failing public-interface test, the minimum fix, then the next test. Reject attempts to skip, delete, or weaken the protected failure.
Review independently
A fresh reviewer chooses checks from the criteria before reading the diff or implementer’s story. Tag findings by severity. Map each change to a criterion.
Exercise the real system
Click the full browser scenario; inspect DOM and network results. Use real test services, dedicated accounts, and a canary with bounded access and spend.
Save the receipts
Keep check output, test diff, browser recording, canary logs, and review findings. Cap review rounds and hand unresolved blockers to a person.
What does a good contract look like?
Illustrative checkout criterion: A signed-in test customer has a $50 cart and a stored address. After choosing standard delivery, the UI shows $0 shipping, and the saved order also contains shipping = 0. Check the DOM and the stored order using the real test database. Complete within the team’s agreed time budget.
For performance claims, define the budget first, run the same scenario on main and the branch several times, and compare medians. Include a mobile viewport. A screenshot or a single local run is insufficient.


05 / A useful opinion, inside a gate
A high average can hide a failure.
The post describes a 1–20 scoring scheme: accept at a mean of at least 14, with a veto for a confident failure. Explore that mechanism below.
ILLUSTRATIVE SCORES · NOT MEASUREMENTS
Completion decision
Each checklist item gets a fresh judge. Scores need explicit anchors; the veto is a separate confident-failure signal in this demo. Code enforces the gate.
Hypothetical independent judges, each with a 10% false-rejection rate: 1 − 0.9K. Correlated judgments would change this calculation. This is not an Atomic measurement.
